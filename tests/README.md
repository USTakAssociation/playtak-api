# Tak Server Test Suite

Integration tests that run against a live Tak server over the wire.
Written in Go so the same suite can target both the Java reference
implementation and the future Go implementation.

---

## Prerequisites

- Go 1.22+
- A running Tak server (Java or Go)
- Three pre-seeded test accounts in the players database

### Creating test accounts

From the repo root run the helper script three times:

```bash
sh scripts/development/add_user.sh testuser1 ./players.db
sh scripts/development/add_user.sh testuser2 ./players.db
sh scripts/development/add_user.sh testuser3 ./players.db
```

All three accounts are created with the password `password`.

---

## Configuration

The suite is configured via environment variables.

| Variable            | Default           | Description                               |
|---------------------|-------------------|-------------------------------------------|
| `TAK_TELNET_ADDR`   | `localhost:10000` | Telnet port of the server under test      |
| `TAK_WS_ADDR`       | `localhost:9999`  | WebSocket port of the server under test   |
| `TAK_HTTP_ADDR`     | `localhost:9998`  | HTTP API port of the server under test    |
| `TAK_SKIP_AUTH_TESTS` | unset           | Set to `1` to skip tests requiring named accounts |
| `TAK_ADMIN_USER`    | unset             | Admin account username for admin tests    |
| `TAK_ADMIN_PASS`    | unset             | Admin account password for admin tests    |

## Running the tests
from the tests folder run the following commands

### Install dependencies
```bash
go mod tidy
```

### Run everything

```bash
go test ./...
```

### Run with verbose output (recommended — shows all ← → messages)

```bash
go test ./... -v
```

### Run a specific test file

```bash
go test -v ./suite/ -run TestAuth
```

### Run a single test

```bash
go test -v ./suite/ -run TestGuestLogin
```

### Run against a non-default server

```bash
TAK_TELNET_ADDR=playtak.com:10000 TAK_WS_ADDR=playtak.com:9999 go test ./...
```

### Run against the beta server

```bash
TAK_TELNET_ADDR=localhost:10002 TAK_WS_ADDR=localhost:10001 TAK_HTTP_ADDR=localhost:10003 go test ./...
```

### Adjusting timeouts

Tests use a 5 second default per-message read timeout.
Override the overall test timeout with:

```bash
go test ./... -timeout 120s
```

### Run with race detector

```bash
go test -race ./...
```

## Test structure

```
tests/
├── README.md                   # this file
├── go.mod
├── go.sum                      # generated by go mod tidy
├── internal/
│   └── client/
│       ├── client.go           # core TCP (telnet) test client
│       ├── websocket.go        # WebSocket variant of the client
│       └── helpers.go          # login flow helpers shared across tests
└── suite/
    ├── config_test.go          # server address + test account helpers
    ├── helpers_test.go         # suite-level game/seek helpers
    ├── connection_test.go      # welcome, quit, unknown commands, ping
    ├── auth_test.go            # login, guest, register, double-login
    ├── protocol_test.go        # Protocol command, version-specific formats
    ├── seek_test.go            # V1-V4 seeks, accept, rematch, private seeks
    ├── game_test.go            # game start, place, move, win conditions
    ├── clock_test.go           # Time vs Timems, give time, increment
    ├── chat_test.go            # shout, tell, rooms
    ├── observe_test.go         # observe, unobserve, spectator messages
    ├── undo_test.go            # undo request, accept, remove
    ├── draw_test.go            # draw offer, accept, remove
    ├── admin_test.go           # sudo commands (requires admin account)
    ├── reconnect_test.go       # disconnect + rejoin within window
    └── websocket_test.go       # WebSocket transport tests
```

## Adding new tests

1. Pick the right file in `suite/` or create a new one
2. Use `client.New(t, telnetAddr(t))` for telnet or `client.NewWS(t, wsAddr(t))` for WebSocket
3. Use the helpers in `internal/client/helpers.go` for login flows
4. Use the suite-level helpers in `suite/helpers_test.go` for seek/game setup
5. Every test gets its own fresh connections — tests must be independent

### Minimal example

```go
func TestMyNewBehaviour(t *testing.T) {
    c := client.New(t, telnetAddr(t))
    client.LoginGuest(t, c)

    c.Send("PING")
    c.Expect("OK")
}
```

## Notes

- Tests that require named accounts will skip automatically if
  `TAK_SKIP_AUTH_TESTS=1` is set
- Admin tests require `TAK_ADMIN_USER` and `TAK_ADMIN_PASS` to be set like so `TAK_ADMIN_USER=adminuser TAK_ADMIN_PASS=password go test ./suite/ -v -timeout 120s 2>&1 | tee test-results.txt`
- Tests are not order-dependent and clean up after themselves via `t.Cleanup`
- Tests do not automatically clean up lingering games though so they need to be cleaned up manually typically by having one of the clients resign unless you complete a game by other avenues
- Guest account names are non-deterministic; tests that care about
  a specific name capture it from the `Welcome <name>!` response
- The `-v` flag is highly recommended during development as it logs
  every message sent and received
- Group tests together with Test{group name} to keep related tests close to each other. which allows you to run grouped tests like so `go test ./suite/ -run TestUndo -v -timeout 120s 2>&1 | tee test-results.txt` which will run all the undo tests
